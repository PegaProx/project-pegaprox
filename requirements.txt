# === Transitive pins (scanner hygiene; newer versions pulled automatically) ===
# MK Sep 2026 — dropped the setuptools floor pin from #608. Since 3.12 ensurepip ships no
# setuptools, so that line was the only reason it was in the image at all, and it dragged
# its vendored wheel 0.46.3 in with it (84.0.0 still vendors 0.46.3, so bumping is no fix).
# Nothing imports setuptools or pkg_resources at runtime; sdists resolve via PEP 517 build
# isolation. Verified on a pip-only venv: all 53 packages install, setuptools absent after.
# MK Sep 2026 - zipp only ever arrives here through Flask's importlib-metadata, which
# Flask itself requires only below 3.10. Without the marker this floor installs a package
# nothing uses on every modern deployment; with it, the CVE floor still applies exactly
# where the package actually turns up. min_python is 3.8, so that case is real.
zipp>=3.19.1; python_version < "3.10"
idna>=3.15
# MK Oct 2026 - brotli only comes in through flask-compress, which takes any version, so a
# `pip install -r` on an existing install never moves it. 1.2.1 fixes an out-of-bounds write
# in the decoder (CVE-2026-111497), and we do decode: urllib3 asks every peer for br and
# inflates the reply itself, so a PVE node, an ESXi host, the IdP or anyone sitting on an
# unverified TLS link can feed it a crafted stream. PyPy gets brotlicffi, same C decoder.
brotli>=1.2.1; platform_python_implementation != "PyPy"
brotlicffi>=1.2.1.0; platform_python_implementation == "PyPy"
